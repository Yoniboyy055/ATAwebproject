## 3. Verification method — and its honest limit

For each file the connector's returned `fileSize`, `title`, `parentId` and `mimeType` were compared against the repository source at commit `6c7d6f2`.

**What that establishes:** the file exists, sits in the correct folder, is readable, carries the right name and MIME type, and matches the source **byte count exactly**. A byte-count match on UTF-8 Markdown of this size is a strong integrity signal — any character substitution, truncation, encoding change or line-ending change would alter it.

**What it does not establish:** the available Drive connector exposes no checksum field, so a **full end-to-end SHA-256 comparison is not obtainable through this interface**. This was reported the same way for the WP-02 delivery and is stated here rather than glossed.

## 4. Connector capability note

The Drive connector available in this session supports `search_files`, `create_file`, `copy_file`, `download_file_content`, `read_file_content`, `get_file_metadata`, `get_file_permissions` and `list_recent_files`. It exposes **no update, delete, trash, move or rename operation**. Consequences:

- A file cannot be replaced in place — a corrected version must be uploaded as a new file and the superseded one trashed manually.
- Obsolete files cannot be removed by this agent. See §6.
